# ADR-001：先建立离线 Rerank 边界，再决定在线切换

> 状态：已接受
> 日期：2026-09-26
> 关联功能：`docs/features/20260926-retrieval-2-rerank-v4.md`

## 背景

当前在线检索采用查询扩展、词法检索、Dense 检索和 RRF 融合。v3 已达到较高召回，
下一步容易直接把 Cross-Encoder 或模型 Reranker 接入在线链路，但这会同时改变排序、
延迟、成本、依赖和生成上下文，难以判断收益来源。

## 候选方案

1. 直接在线接入 BGE/Cross-Encoder Reranker。
2. 直接调用 LLM 对候选证据排序。
3. 先建立模型无关的离线 Rerank 接口和确定性对照，再用独立 v4 决定是否引入模型。
4. 不引入 Rerank，继续只优化召回。

## 决策

采用方案 3。

- 上游先召回 Top-30，再由 `EvidenceReranker` 输出 Top-5。
- 首版使用 `deterministic-evidence-v1`，不增加依赖和商业调用。
- 策略名独立为 `expanded-hybrid-rerank-v1`，在线默认仍为 `expanded-hybrid-rrf-v1`。
- v3 只作回归，v4 才作为本轮独立泛化证据。
- 只有 v4 显示 Recall 不降且排序或质量指标提升，才讨论在线切换。

## 原因

- 将候选扩展、排序算法和在线切换解耦，避免一次改动多个变量。
- 先建立 nDCG、P95 和失败样本口径，再决定是否值得承担模型 Reranker 的延迟和部署成本。
- 46 条 v3 已被观察，不能继续证明新策略泛化。

## 影响

- 增加一层内部 Service 和协议，但不修改公开 API 或数据库。
- 离线评估多一次 CPU 排序，不新增模型费用。
- 模型 Reranker 的最终引入仍需要独立 ADR 或扩展现有 ADR。

## 回滚条件

- v4 Recall@5 下降，或 nDCG/MRR 无明确提升。
- 重排 P95 增量超出设定预算。
- 候选重复或同作品占位导致多证据问题退化。

回滚只需移除组合层和评估脚本策略选项，不影响数据库、在线问答或历史报告。

## 复查时间

v4 真实报告生成后立即复查。
