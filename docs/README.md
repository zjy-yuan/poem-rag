# 文档导航与维护规则

> 项目：Poem RAG  
> 文档状态：v0.1  
> 创建日期：2026-09-19  
> 适用范围：项目规划、需求设计、前后端开发、RAG 实验、测试、部署和复盘

## 1. 文档职责

项目文档不追求数量，重点是每类信息只有一个稳定归属，避免同一份内容在多个文件中重复维护。

| 文档 | 负责回答 | 更新时机 |
| --- | --- | --- |
| [README](../README.md) | 项目是什么、如何启动、常用命令 | 启动方式或工程入口变化 |
| [项目说明](PROJECT_GUIDE.md) | 当前系统由什么组成、代码如何流转、现在做到哪 | 每个可验收功能完成后 |
| [开发流程](DEVELOPMENT_WORKFLOW.md) | 一个需求从提出到验收要走哪些步骤 | 工程规则变化 |
| [前后端契约](FRONTEND_BACKEND_CONTRACT.md) | 页面、API、响应、数据边界如何设计 | 接口设计变化前 |
| [开发日志](DEVELOPMENT_LOG.md) | 每个阶段做了什么、为什么、结果如何 | 每次有产出的工作结束后 |
| [功能设计模板](features/README.md) | 跨模块功能如何在编码前完整设计 | 新功能启动时复制模板 |

### 1.1 唯一事实源

1. 接口的目标设计以 `FRONTEND_BACKEND_CONTRACT.md` 为准。
2. 接口的运行时事实以 FastAPI `/openapi.json` 和 `/docs` 为准。
3. 目标契约与 OpenAPI 不一致属于缺陷，必须先修正文档或代码，不能靠口头约定。
4. 数据库结构的唯一执行入口是 Alembic 迁移，不以 ORM 模型自动建表代替正式迁移。
5. 当前系统状态只写在 `PROJECT_GUIDE.md`，历史过程和决策原因只追加到 `DEVELOPMENT_LOG.md`。
6. 密钥、数据库密码、Token、API Key 和真实 `.env` 内容不得写入任何文档。

## 2. 默认变更顺序

除纯文案或极小修复外，功能按以下顺序推进：

```text
需求与验收标准
  -> 影响面分析
  -> 功能设计文档或 ADR（达到门槛时）
  -> 更新前后端契约
  -> 数据库迁移
  -> 后端实现与测试
  -> 前端实现与测试
  -> 真实联调与验收
  -> 更新项目说明和开发日志
```

这个顺序不是为了让文档拖慢编码，而是为了保证以下问题在写代码前已经回答：

1. 用户要完成什么任务，什么结果算完成？
2. 数据由谁保存，谁有权读写，失败时怎么办？
3. 前端调用哪个接口，请求和响应是什么？
4. 改动会不会破坏已有数据或已有页面？
5. 用什么测试或指标证明改动有效？

## 3. 变更与文档对应关系

| 变更类型 | 编码前必须确定 | 完成后必须更新 |
| --- | --- | --- |
| 页面或交互 | 页面路由、状态、空态、错误态、权限 | 项目说明、开发日志 |
| API | 方法、路径、请求、响应、错误码、权限 | 前后端契约、OpenAPI、开发日志 |
| 数据库 | 表、字段、索引、约束、迁移、回滚 | 迁移、项目说明、开发日志 |
| 权限与安全 | 资源所有者、角色、越权场景 | 前后端契约、测试、开发日志 |
| RAG 策略 | 语料版本、切块、模型、检索、指标 | 评估报告、项目说明、开发日志 |
| 异步任务 | 任务状态、幂等、重试、超时、失败恢复 | 前后端契约、项目说明、开发日志 |
| 部署 | 环境变量、服务拓扑、健康检查、回滚 | README、部署文档、开发日志 |

## 4. 功能设计文档门槛

满足以下任一项时，在 `docs/features/` 新建功能设计文档：

1. 预计超过 1 个开发日。
2. 同时修改数据库、后端和前端。
3. 新增或改变公开 API。
4. 改变权限、数据生命周期、异步任务或缓存语义。
5. 改变切块、Embedding、检索、重排、Prompt、模型或评估基线。

只影响一个模块的文案、样式和小修复，可以直接开发，并在开发日志中说明。

## 5. 文档状态标记

功能文档和接口条目可使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `设计` | 已讨论，尚未编码 |
| `进行中` | 正在实现，契约仍可能变化 |
| `已实现` | 代码和测试已通过验收 |
| `已废弃` | 保留历史说明，不应继续使用 |

没有状态标记时，默认表示目标设计，并不自动代表已经实现。

## 6. 推荐阅读顺序

第一次理解项目时按以下顺序阅读：

1. `README.md`
2. `docs/PROJECT_GUIDE.md`
3. `docs/DEVELOPMENT_WORKFLOW.md`
4. `docs/FRONTEND_BACKEND_CONTRACT.md`
5. `docs/DEVELOPMENT_LOG.md` 中最近三次记录

开发具体功能时，从页面入口或 API 路由开始，沿着“页面/路由 -> API -> Schema -> Service -> Repository -> Model -> Migration -> Test”追踪，不要只阅读孤立代码片段。
