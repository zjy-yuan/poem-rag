## 1. 背景与问题

此前生成层评估只有 12 条种子样本，且最终为 `12/12`。该结果只能证明种子语料上的
固定回归没有退化，不能回答以下问题：

1. 在线 `expanded-lexical-v1` 能否覆盖开放语料中的长诗、长词和自然语言问题。
2. 父级上下文能否把作品级信息带入 `assess` 和生成节点。
3. 领域内缺实体、缺属性和跨域问题是否稳定拒答。
4. 检索层“命中作品标题”与生成层“证据真的能回答问题”之间的差距有多大。

因此新增一份独立 holdout，不复用检索集的 50 条问题，也不通过修改 Prompt 掩盖
检索和证据组装缺陷。

## 2. 目标

1. 新增 20 至 30 条与 `open-corpus-100-v1` 语料快照绑定的生成评估样本。
2. 覆盖真实作品事实、自然语言、长诗长词、多证据和三类拒答边界。
3. 直接运行在线 `RagChatGraph`，保留每个样本的独立 Session。
4. 记录答案事实、引用召回/精确率、拒答 P/R/F1、延迟和受控错误。
5. 将默认生成评估入口切换到开放语料 holdout，旧 12 条种子集保持冻结。

## 3. 非目标

1. 不把 28 条样本当作统计显著结论或生产准确率。
2. 不引入 LLM-as-judge、忠实度蕴含或人工文学赏析评分。
3. 不在本轮直接切换在线检索策略。
4. 不提交含第三方完整正文的评估报告。
5. 不因为某条样本失败就修改事实词或引用金标准来制造通过。

## 7. 失败分析

本轮修复前曾有四个失败样本，均为有答案问题被 `assess` 判为 `missing_fact`：

| 样本 | 在线入选 | 根因 |
| --- | ---: | --- |
| `gen-open-qingyuan-lantern` | 8/25 | 检索命中相关注释，但没有把“众里寻他千百度”“灯火阑珊处”所在行带入有效证据 |
| `gen-open-pipa-music` | 5/25 | 目标比喻句未进入 Top-K，父级诗词 chunk 在 1200 字处截断 |
| `gen-open-kongque-tragedy` | 5/25 | 2389 字长诗的爱情悲剧结尾未进入上下文预算 |
| `gen-open-multi-moon` | 6/118 | 多证据问题没有保证两首目标作品同时进入有效上下文 |

关键结论：

1. `assess` 的行为是合理的。它拒绝了只有相关主题、没有回答核心事实的证据。
2. 失败集中在在线 `expanded-lexical-v1` 的召回和父级上下文预算，不是 Prompt 或
   拒答文案问题。
3. 检索集的标题级金标准可能把“命中某条注释”算作作品命中；生成层 holdout 因此
   暴露了“作品命中不等于答案证据命中”的评估缺口。
4. 长诗需要按事实位置或语义段落扩展证据，不能继续只截取作品前 1200 字。
5. 多证据问题需要按目标作品扩展，而不是只增加全局 Top-K。

本轮修复措施：

1. 查询词典新增 `lantern_festival`、`longing` 和作者“辛弃疾”，并让领域概念触发
   词覆盖朝代字符，避免“元宵”被误识别为“元”朝。
2. 识别“两首、分别、各自、对比”等多证据意图；显式多证据查询限制单个作品最多
   占用 2 个候选槽位，再用剩余候选补满，保证跨作品覆盖。
3. 父级上下文从固定前几条改为按作品轮转选择，预算调整为 40 chunks / 4800 字符，
   长诗尾部事实不再因为只取前 1200 字而丢失。
4. `gen-open-jiangchengzi-dream` 的金标准补充“窗前梳妆、相看无言、泪流千行”等
   同义表达；这是评测短语口径修正，不是放宽模型回答要求。

修复后，`gen-open-qingyuan-lantern`、`gen-open-multi-moon`、
`gen-open-pipa-music`、`gen-open-kongque-tragedy` 和
`gen-open-jiangchengzi-dream` 全部通过，生成 holdout 达到 `28/28`。

## 9. 风险与回滚

1. 28 条样本仍不足以完成统计显著评估。
2. `required_facts` 仍是关键词匹配，不能证明回答被证据蕴含。
3. 当前引用金标准只验证作品级定位，不能保证引用片段覆盖事实。
4. 本轮词典和候选槽位针对当前 holdout 暴露的失败类型修改，需要在新的独立 holdout
   上复核，不能把 `28/28` 直接当作生产准确率。
5. 4800 字上下文预算是当前 DeepSeek 配置的工作点，尚未按模型上下文窗口和 token
   成本做系统调参。
6. 真实报告包含模型回答和第三方引用正文，必须保持本地忽略。
7. 如需回滚，可继续显式传入 `--dataset data/eval/generation_rag_v1.json`，不影响
   在线 HTTP 和 SSE 契约。

## 10. 后续方向

1. 增加新的独立生成 holdout，复核本轮词典和候选槽位是否泛化。
2. 增加“答案证据选择器”，区分作品命中、事实片段命中和上下文补充命中。
3. 为长诗建立按段、韵脚或事实位置的上下文扩展策略，并记录 token 成本。
4. 在同一评估集上对比 `hybrid-rrf-v1 + 0.60`、Rerank、父级上下文和 `assess` 的组合。
5. 在独立 holdout 稳定后，再决定是否切换在线检索策略和 Embedding 维度。
