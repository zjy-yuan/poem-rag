# 开放语料检索评估 v1

> 后续说明：本文指标基于 100 首语料快照，保留用于复现历史决策。原 50 条集已在
> 1000 首候选池上重跑，当前结果和后续判断见
> [1000 首真实语料扩库](20260923-chinese-gushiwen-1000-corpus.md)。

> 状态：已实现
> 创建日期：2026-09-20
> 最近更新：2026-09-20
> 关联任务：让检索评估与 100 首真实语料同步，区分召回能力、元数据能力、多证据能力和拒答能力

## 1. 背景与问题

原有 `retrieval_lexical_v2.json` 只覆盖 6 首种子诗词。扩库到 100 首真实语料后，
旧集无法表达新作品、长诗长词、候选歧义和领域内无答案问题。继续在该集上调阈值会
把“语料变化”误当成“策略变化”，也无法判断 Dense、Expanded 和 Hybrid 的真实边界。

因此需要冻结一份与当前 100 首语料快照绑定的开放语料评估集，同时保留旧集用于历史
复现。新集的目标不是证明某个策略“准确率很高”，而是稳定暴露各策略的失败类型。

## 2. 目标

1. 用 50 条人工金标准覆盖真实导入作品和主要查询形态。
2. 明确区分精确引用、短语、标题、作者、朝代、多证据、自然语言、长文本和无答案。
3. 作者和朝代查询允许任意同作者、同朝代证据命中，不把某一首代表作当作唯一答案。
4. 让默认离线评估入口使用开放语料集，旧集保持冻结。
5. 用同一环境对比 Lexical、Expanded、Dense 和 Hybrid，记录失败样例而非只报总分。

## 3. 非目标

1. 不把当前 50 条样本当作生产准确率或统计显著结论。
2. 不修改公开 HTTP 检索契约，也不在本轮切换在线问答策略。
3. 不在同一评估集上反复调阈值后宣称泛化能力。
4. 不引入跨来源去重、Rerank 或结构化过滤实现。
5. 不提交含第三方完整正文的检索报告。

## 6. 结果解读

### 6.1 Lexical

- 精确引用、短语、标题、作者和朝代全部通过。
- 自然语言 9 条全部失败，长文本 4 条全部失败。
- 词法基线适合精确引用和元数据召回，但不能承担开放自然语言入口。

### 6.2 Expanded

- Recall@5 从 `0.678571` 提升到 `0.797619`，自然语言从 0 提升到 4/9，
  长文本从 0 提升到 1/4。
- 改写变体引入了新的误召回，无答案准确率从 `1.0` 降到 `0.375`。
- 本轮补充元宵、怀人和“辛弃疾”后，自然语言事实召回有所提升；多证据查询也开始
  限制单个作品的候选槽位，但当前词典仍是有限映射，不足以单独承担开放查询改写。

### 6.3 Dense 与 Hybrid

- Dense 将自然语言和长文本召回提升到 9/9、4/4，可回答无结果率为 0。
- Dense 和 Hybrid 在无阈值时会召回跨域负样本，说明“有相似内容”不等于“能回答问题”。
- Hybrid + `0.50` 通过 43/50；Hybrid + `0.60` 通过 47/50，且可回答无结果仍为 0。
- `0.60` 是当前样本上的候选工作点，不是已经完成独立验证的生产阈值。

### 6.4 剩余失败

`hybrid-rrf-v1 + 0.60` 仍有三条失败：

| 样本 | 类型 | 说明 |
| --- | --- | --- |
| `multi-east-wind-01` | 多证据 | Top-5 未同时覆盖两个目标作品 |
| `no-answer-missing-xiangsi-01` | 领域内缺实体 | 《相思》不在库中，但返回了相近证据 |
| `no-answer-jiangjinjiu-year-01` | 领域内缺属性 | 作品在库中，但正文和注释没有创作年份 |

这三条说明后续需要分别处理多证据扩展和可答性判定，不能继续通过单一相似度阈值解决。

## 7. 决策

1. 开放语料评估与种子评估分版本保存，不原地覆盖旧集。
2. 默认评估入口切换到 `open-corpus-100-v1`，旧集只用于历史复现。
3. 在线检索策略暂不切换；先让评估口径覆盖上下文组装和可答性节点。
4. `0.60` 只作为后续候选配置，必须在新 holdout 集或人工盲评上复核。
5. 多证据和领域内无答案分别评估，不把两类失败合并成一个“准确率”。

## 8. 测试

`apps/api/tests/test_retrieval_evaluation.py` 新增开放语料契约测试，校验：

- 数据集版本和 50 条规模。
- 42 条可回答、8 条无答案。
- 样本 ID 和问题文本唯一。
- 十一类评估场景全部存在。

## 9. 风险与后续

1. 当前 50 条样本适合发现策略边界，但不足以做稳定阈值校准。
2. 语料中仍有跨来源重复作品，可能影响多证据排名。
3. 评估脚本尚未接入父级上下文装饰器和在线 `assess` 节点，当前指标只代表检索层。
4. 下一步应增加 20 至 30 条 holdout 样本，并评估“检索 + 上下文组装 + 可答性判定”。
5. Rerank 应单独报告召回阶段和排序阶段变化，不能与阈值调整混在一起。
6. 本轮词典扩展来自生成 holdout 的失败样本，需要在新问题上复核，避免把局部修补
   当作通用查询理解能力。
