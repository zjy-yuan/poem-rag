# 领域标签独立盲标采样

> 状态：已实现（采样清单待人工标注）
> 创建日期：2026-09-27
> 最近更新：2026-09-27
> 关联任务：在首批同源金标准之外建立独立的 24 首人工标注候选清单

## 1. 背景与问题

`domain-label-gold-v1` 的 5 首作品来自已经完成审核的导入样本。当前 micro/macro
P/R/F1 为 `1.0`，只能证明评估器与既有审核结果一致，不能证明标签器或导入标签对
未观察作品具有泛化能力。

直接人工挑选补充样本容易受到“选择熟悉作品”和“看过 AI/导入标签后再下结论”的
影响。因此本切片先建立一份固定的盲标清单：选样过程只读取公开来源作品正文，不读取
标签预测，不把 AI、公开数据集或既有审核标签写入候选文件。

## 2. 目标

- 从当前已发布语料中确定 24 首、四个分层各 6 首的人工标注候选。
- 排除 `domain-label-gold-v1` 中的 5 首作品，避免重复计入独立样本。
- 固定随机种子、排序规则、作者上限和来源范围，使选样结果可复现。
- 为每首作品保留稳定定位、当前正文哈希、行号文本和空白人工标签位。
- 只生成离线清单，不在数据库创建标签关联，不改变审核状态。

## 3. 非目标

- 不自动生成 imagery、emotion、theme 或 allusion 标签。
- 不把公开数据集标签或 AI 推断混入候选清单。
- 不评估标签质量，也不开启在线标签过滤、查询改写或重排。
- 不设计新的数据库表、公开 API 或前端页面。
- 不保证分层字段等价于严格体裁分类；它只用于控制采样结构。

## 4. 用户场景与验收标准

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 准备独立人工样本 | 运行采样 CLI | 输出 24 首作品，四个分层各 6 首 |
| 核对样本独立性 | 对比 v1 金标准 | 候选与 v1 的 5 个 `external_id` 完全不相交 |
| 开始人工标注 | 打开清单 | 每条 `annotation_status=pending`，四个维度均为空列表 |
| 复现选样 | 使用相同来源、数量和种子重跑 | 选中作品集合一致；`generated_at` 可不同 |
| 复核正文版本 | 对照来源内容哈希 | 哈希不一致时停止采样并要求复核版本 |

## 5. 方案概览

```text
已发布且未删除作品
  -> 固定 source_key
  -> 排除 v1 external_id
  -> 校验 source.content_hash == 当前 PoemVersion 正文哈希
  -> title / line_count / dynasty 分层
  -> sha256(seed + "\0" + external_id) 确定性排序
  -> 每作者最多 2 首
  -> 每层 6 首
  -> 输出待人工填写的 JSON 清单
```

默认来源为 `aopao-chinese-gushiwen`，默认种子为 `domain-label-gold-v2`。四个分层：

1. `tang-poem`：唐代非长文本作品。
2. `song-work`：宋代非长文本作品。
3. `other-dynasty`：其他朝代的非长文本作品。
4. `long-text-or-ci`：正文至少 10 行，或标题包含 `·` 的作品。

分层是可解释的采样桶，不是严格题材或体裁标注。标题不含 `·` 且正文较短的词作仍可能
进入朝代分层；本轮不在看过候选后调整规则，以免破坏盲标和冻结边界。

## 6. 接口与契约

本切片不新增 HTTP API。CLI 为：

```powershell
.\.venv\Scripts\python.exe apps\api\scripts\prepare_domain_label_gold_sampling.py
```

可选参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--source-key` | `aopao-chinese-gushiwen` | 限定语料来源 |
| `--count` | `24` | 候选总数，至少为 4 |
| `--seed` | `domain-label-gold-v2` | 确定性排序种子 |
| `--exclude` | `data/eval/domain_label_gold_v1.json` | 排除已有金标准作品 |
| `--output` | `data/eval/domain_label_gold_v2_sampling.json` | 输出文件 |

输出使用 `DomainLabelSamplingManifest`。Schema 强制：

- `sampled_count == len(records)`。
- `external_id` 唯一，且不能与 `excluded_external_ids` 相交。
- `line_count` 与 `line_numbered_content` 一致。
- 每条 `manual_labels` 必须为空。

## 7. 数据设计

本切片不新增表、不新增迁移，也不写 MySQL。清单记录保留：

- `poem_id`、`version_id`、`external_id`：用于后续回查当前作品版本。
- `title`、`author`、`dynasty`、`source_name`、`source_url`：人工理解来源。
- `content_hash`、`line_count`、`line_numbered_content`：冻结标注证据。
- `stratum`、`annotation_status`、`manual_labels`、`review_note`：标注工作区。

后续人工填写时只修改 `manual_labels` 与必要的 `review_note`，不得修改正文哈希或
行号文本。清单转换为 `domain-label-gold-v2` 前仍需独立校验，不能直接把采样文件当作
金标准。

## 8. 后端设计

- `apps/api/app/schemas/domain_label_sampling.py`：定义清单、记录、空白标签位和校验。
- `apps/api/app/evaluation/domain_label_sampling.py`：实现只读候选加载、正文哈希
  校验、分层、确定性排序和作者上限。
- `apps/api/scripts/prepare_domain_label_gold_sampling.py`：连接 MySQL，读取 v1
  排除项并写出清单。
- `apps/api/tests/test_domain_label_sampling.py`：覆盖确定性、分层、排除、空白标签、
  哈希不一致、Schema 和冻结文件契约。

采样器不读取标签表，不调用在线检索或模型，不写业务表，也不重建索引。

## 9. 前端设计

不涉及。当前标注清单是开发期文件，为人工审阅服务；后续只有在标注流程需要多人协作
和权限隔离时，才评估独立管理页面。

## 10. RAG 与评估

这 24 首只形成候选池，不是新的 precision/recall 金标准。用户完成人工标注后，下一
切片需要：

1. 将逐首人工结果转换为独立 `domain-label-gold-v2` Schema。
2. 冻结每首作品的正文哈希、证据行号、`critical` 级别和维度目标数。
3. 将 v1 与 v2 分开统计，不能把 v1 的同源结果混入独立样本指标。
4. 达到覆盖阈值后再决定是否进行在线标签过滤或重排实验。

## 11. 测试计划

| 层级 | 覆盖内容 |

| 单元测试 | 确定性排序、分层配额、作者上限、哈希不一致 |
| Schema | 数量一致性、排除项不相交、空白人工标签、行数一致 |
| 文件回归 | 冻结清单 24 首、四层各 6 首、排除 v1、全部空白 |

| 人工验收 | 按诗体、证据和四维度逐首填写，另行冻结为 v2 金标准 |

## 12. 风险与回滚

1. 分层启发式不能替代严格体裁元数据；它只控制样本结构，不会写入作品分类。
2. 人工标注仍可能受标注者知识边界影响，后续需要明确标注规则和第二人复核。
3. 来源正文或当前版本发生变化时，哈希校验会阻止采样；此时应新建版本，不复用旧清单。
4. 输出文件含公开来源正文和 URL，仓库只用于技术展示；不扩大到未确认许可的数据。
5. 回滚只需删除本切片新增的 CLI、Schema、测试和清单，不涉及数据库或在线服务。
