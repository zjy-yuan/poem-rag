# 可答性评估集 v2 与拒答指标

> 状态：已实现  
> 创建日期：2026-09-20  
> 最近更新：2026-09-20  
> 关联任务：领域内无答案样本、拒答 P/R/F1、相关性门槛重新标定

## 1. 背景与问题

`lexical-baseline-seed-v1` 的 27 条样本里，4 条无答案样本全部是跨域问题（量子纠缠、
火星探测器、赋税制度、人工智能训练数据）。这个设计让门槛看起来比实际更有效：

1. 跨域问题与诗词语料的余弦相似度天然很低，任何合理阈值都能拒绝。
2. 评估集没有“领域内、但语料里没有答案”的样本，因此无法回答“用户问诗人生平、
   创作年代、作品背景时系统会不会编”。
3. 评估只有 `unanswerable_accuracy`，它只统计“该拒的拒了多少”，看不出“该答的被
   误拒了多少”。一个把所有问题都拒答的系统也能拿到满分。

因此本切片补齐负样本类型和拒答指标，再重新标定门槛。

## 2. 目标

- 把无答案样本拆成跨域、领域内缺实体、领域内缺属性三类，并明确各自的判定语义。
- 增加拒答精确率、召回率和 F1，与 `answerable_no_result_rate` 联合阅读。
- 在 v2 上重跑 lexical、expanded、dense、hybrid，重新判断 `min_score` 是否仍然成立。
- 冻结 v1 数据集文件，保证历史报告仍可复现。

## 3. 非目标

- 不修改公开 HTTP 接口和在线检索策略。
- 不实现答案级忠实度、引用准确率或人工文学评分，这些属于生成层评估。
- 不实现 LLM 可答性判定节点；本切片只负责用数据说明它为什么必要。
- 不为了指标好看而删除失败样本。

## 4. 用户场景与验收标准

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 跨域提问 | 问“量子纠缠的物理实验” | 检索为空，拒答 |
| 领域内缺实体 | 问“杜甫《春望》的创作背景” | 语料没有该作者和作品，检索应为空 |
| 领域内缺属性 | 问“李白的出生地在哪里” | 语料有李白作品但没有生平原句，不应把诗句当作答案证据 |
| 该答不拒 | 问“表达思乡情绪的诗句” | 必须返回证据，不能被门槛误拒 |
| 历史可复现 | 重跑 v1 报告 | v1 数据集文件与语义保持不变 |

## 5. 方案概览

```text
data/eval/retrieval_lexical_v1.json   # 冻结，27 条，历史报告仍可复现
data/eval/retrieval_lexical_v2.json   # 现行默认，31 条，拆分无答案类别
  -> RetrievalEvaluator 逐条检索
  -> 汇总 Recall/MRR/Hit Rate
  -> 汇总拒答 precision/recall/F1
  -> 控制台摘要 + 完整 JSON 报告
```

关键语义决定：`expected=no_evidence` 表示“这条证据不应当被用来回答该问题”，即
**可答性相关**，而不是“话题相关”。检索到与提问实体同名但答不出所问属性的段落，
仍记为失败。这条定义让检索层与生成层的责任边界显式化：检索层要么交出能回答问题的
证据，要么明确交白卷。

## 6. 接口与契约

本切片不新增 HTTP 接口，SSE 事件结构和错误码不变。

评估脚本默认数据集从 `retrieval_lexical_v1.json` 切换为 `retrieval_lexical_v2.json`，
可用 `--dataset` 显式指定 v1 复现历史报告。摘要新增一行：

```text
refusal_precision=... refusal_recall=... refusal_f1=...
```

指标定义（以无答案样本为正类）：

| 指标 | 定义 |
| --- | --- |
| 拒答 TP | 无答案样本且检索为空 |
| 拒答 FP | 有答案样本但检索为空（误拒） |
| 拒答 FN | 无答案样本但检索非空（漏拒） |
| 拒答精确率 | `TP / (TP + FP)` |
| 拒答召回率 | `TP / (TP + FN)` |
| 拒答 F1 | 精确率与召回率的调和平均 |

## 7. 数据设计

`data/eval/retrieval_lexical_v2.json`（`lexical-baseline-seed-v2`）共 31 条：23 条
有答案 + 8 条无答案。

| 分类 | 数量 | 说明 |
| --- | ---: | --- |
| `no_answer_cross_domain` | 4 | v1 原有跨域问题，重命名类别 |
| `no_answer_in_domain_missing_entity` | 1 | `杜甫《春望》的创作背景`，作者与作品均不在语料 |
| `no_answer_in_domain_missing_attribute` | 3 | `李白的出生地在哪里`、`静夜思写于哪一年`、`苏轼被贬黄州的经历` |

v1 文件不改动，历史报告中的 `dataset_version=lexical-baseline-seed-v1` 仍指向可复现的
数据集；v2 只新增样本和类别，不修改任何 v1 样本的问题或金标准。

当前 6 首种子作品没有任何注释类 chunk，正文之外的信息（生平、创作年代、贬谪经历）
在检索层确实不存在，因此上述 4 条负样本在当前语料下是真实无答案的。

### 10.1 余弦分数分布：Dense 单路无法用阈值分离

从 `retrieval_dense_v2_raw_20260920.json` 取每条样本的最高相似度：

| 样本组 | 最高相似度区间 | 具体值 |
| --- | --- | --- |
| 跨域无答案（4 条） | 0.1429 ~ 0.1947 | 0.1429、0.1442、0.1451、0.1947 |
| 领域内无答案（4 条） | 0.3652 ~ 0.4887 | 0.3652、0.4121、0.4747、0.4887 |
| 最弱可回答（4 条） | 0.2647 ~ 0.4513 | 宋 0.2647、唐 0.2870、马致远 0.3971、李清照 0.4513 |

可回答样本与领域内负样本**互相交错**：

1. 要把 4 条领域内负样本全部拒绝，阈值必须高于 `0.4887`，这会同时丢掉宋、唐、
   马致远、李清照 4 条可回答样本。
2. 要保住全部可回答样本，阈值必须不高于 `0.2647`，此时 4 条领域内负样本全部漏拒。
3. 因此 Dense 单路**不存在**能同时满足两侧的全局阈值；`0.22` 只能防跨域漂移，
   不能承担可答性判定。

`dense-baseline-v1` + `0.50` 这一行也说明了为什么不能只看拒答 F1：它的 F1（0.8）
高于 `0.22`（0.667），但可回答无结果率从 0 升到 0.174，拒答精确率降到 0.667，
即为了多拒 4 条错问题，代价是误拒 4 条对问题。

### 10.2 Hybrid 可以承受更高门槛，但依赖词法分支兜底

Hybrid 在 `min_score=0.50` 时达到 31/31 且召回不掉，原因是宋、唐、马致远、李清照
这 4 条低相似度可回答样本由词法分支独立召回，门槛只作用于 Dense 分支。换句话说，
**门槛不伤召回是因为词法分支覆盖了它，而不是因为门槛本身更聪明**。一旦语料扩大到
词法无法命中的改写问法，这条结论就会改变。

因此本切片不把 `0.50` 写入在线配置：在线策略仍是 `expanded-lexical-v1`，
`0.22` 仍只是 Dense 分支的记录值，且它与最差负样本 `0.4887` 之间的间隔只有
`0.0113`，建立在 31 条样本上，不足以作为生产常数。

### 10.3 在线路径的已知缺口

`expanded-lexical-v1` 在 v2 上失败 2 条：

1. `no-answer-in-domain-libai-birthplace-01`：查询改写命中已知作者“李白”，于是召回
   李白的诗作，而问题问的是生平。
2. `no-answer-in-domain-sushi-exile-01`：同理命中苏轼作品，而问题问的是贬谪经历。

两者都不是字符串匹配错误，而是“话题命中、答案缺失”。这说明在线路径需要一层
可答性判定，而不是继续调阈值。

## 12. 风险与回滚

1. 领域内负样本仍只有 4 条，且集中在“生平/年代/经历”三类事实，不能代表全部
   不可答类型。
2. 短查询（单字朝代名）与领域内负样本的分数区间重叠，说明该门槛对查询长度敏感。
3. 当前语料没有注释和赏析 chunk，负样本“无答案”成立；一旦导入赏析与背景语料，
   这些样本可能变成可回答，必须重新标注而不是沿用旧标签。
4. 新增字段使旧报告 JSON 不再符合当前 Schema；旧文件保留为历史产物，不再被脚本读取。
5. 回滚方式是把脚本默认数据集改回 v1，并忽略新指标字段；无迁移、无数据变更。
